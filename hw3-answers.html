(d) Two processes exchange messages. Receive blocks until a message from the named process arrives; Send never blocks.

When both processes start, they immediately call Receive and block while waiting for a message from the other process. Since neither process can reach its Send instruction, neither message is ever created. This is a deadlock because both processes are waiting for an event that only the other blocked process can cause. The resources involved are consumable resources, specifically messages.

Increasing the mailbox capacity would not solve the problem because the issue is not a lack of storage space. Neither process sends a message, so there is nothing to store.

To fix the deadlock, Process A can send its message before attempting to receive:

Process A:
```
Send(to B, request);
Receive(from B, reply);
```

Process B:
```
Receive(from A, request);
Send(to A, reply);
```

With this change, Process A sends the request, Process B receives it and sends a reply, and Process A receives the reply. Both processes can now complete without deadlocking.

(e) If a request in (c) led to an unsafe state, does that mean the processes would be deadlocked once it was granted? Explain the difference between unsafe and deadlocked, and describe a way the processes could all still finish from that unsafe state.

No, an unsafe state does not necessarily mean the processes are deadlocked. An unsafe state means the operating system cannot guarantee that every process will finish if each process requests its maximum remaining resources. A deadlocked state means processes are actually blocked and cannot proceed because they are waiting for resources that cannot become available.

For example, granting P2's request in part (c) would leave the available vector at (3, 2, 0), which is unsafe. However, if P2 could finish without requesting additional resources, it would release its allocation (2, 1, 1), increasing the available vector to (5, 3, 1). The remaining processes could then finish in the order P4 → P3 → P5 → P1.

Therefore, an unsafe state creates the possibility of deadlock, but deadlock is not guaranteed.

(e) Give one advantage and one disadvantage of running the detection algorithm at every request rather than periodically. Then explain how this algorithm differs from the banker's safety test: which matrix does each use, and why is detection called optimistic?

Advantage: Running detection after every request identifies deadlocks immediately, allowing faster recovery.

Disadvantage: It increases CPU overhead because the detection algorithm runs after every resource request.

Difference: Deadlock detection uses the request matrix (Q) and allocation matrix (A) to identify existing deadlocks. The banker's safety test uses the claim matrix (C) and allocation matrix (A) to calculate remaining needs (C − A) and determine whether a state is safe before granting a request.

Why detection is optimistic: It assumes processes will usually complete successfully, allowing resource requests without checking future safety and detecting and recovering from deadlocks only if they occur.

Problem 4The dining philosophers

(a) Write a schedule (a list of steps such as "philosopher 2 picks up fork 2") that ends in deadlock. At the end, who holds which fork and who waits for which? Show how each of the four conditions appears.

Schedule: Philosophers 0, 1, 2, 3, and 4 each pick up their left forks (forks 0, 1, 2, 3, and 4). They then each attempt to pick up their right forks, but all are already held.

Holds and waits:
- P0 holds fork 0, waits for fork 1.
- P1 holds fork 1, waits for fork 2.
- P2 holds fork 2, waits for fork 3.
- P3 holds fork 3, waits for fork 4.
- P4 holds fork 4, waits for fork 0.

Four deadlock conditions:
- Mutual exclusion: Only one philosopher can hold each fork.
- Hold and wait: Each philosopher holds one fork while waiting for another.
- No preemption: Forks cannot be forcibly taken away.
- Circular wait: P0 → P1 → P2 → P3 → P4 → P0.

All five philosophers are deadlocked because none can obtain their second fork or finish eating.

(b) A fix adds semaphore room = 4: each philosopher calls semWait(room) before picking up any fork and semSignal(room) after putting both down. Explain why deadlock is now impossible. What happens if room starts at 5 instead? What is the largest starting value that still rules deadlock out?

Why room = 4 works: Only four philosophers can attempt to pick up forks simultaneously, leaving at least one fork free. This allows a philosopher to obtain both forks, eat, and release them, preventing deadlock.

If room = 5: All five philosophers could pick up their left forks simultaneously and wait for their right forks, causing circular wait and deadlock.

Largest safe starting value: 4.

(c) Another fix leaves the original code alone except for philosopher 4, who picks up fork 0 first and then fork 4. Explain, using the idea of numbering resources, why no circular wait can form. Which of the four conditions does this fix rule out?

By having philosopher 4 pick up fork 0 before fork 4, every philosopher now acquires forks in increasing numerical order. This prevents a circular chain of processes waiting for lower numbered resources, so no circular wait can form. The deadlock condition eliminated is circular wait.

(d) Now the forks are interchangeable and sit in one pile in the middle of the table. A hungry philosopher takes forks from the pile one at a time and keeps any fork already taken while waiting for a second. What is the smallest number of forks in the pile that guarantees no deadlock for the five philosophers? Give the general rule for n processes that each need k units of one resource, taken one unit at a time, and use it for 8 processes that each need 3 tape drives.

Minimum forks: 6. With five forks, each philosopher could hold one and wait for another, causing deadlock. With six forks, at least one philosopher can obtain two forks, finish eating, and release them.

General formula: R = n(k − 1) + 1, where n is the number of processes and k is the number of resource units each process needs.

Eight processes needing three tape drives: R = 8(3 − 1) + 1 = 17 tape drives.

(e) A different design lets a philosopher pick up forks only when both are free, taking the two together in one indivisible step. Explain why this design can never deadlock, and then describe a pattern of meals by philosophers 1 and 3 that could keep philosopher 2 hungry forever. What is the name for that problem, and how does it differ from deadlock?

Why deadlock is impossible: Requiring philosophers to acquire both forks simultaneously eliminates the hold-and-wait condition. A philosopher either gets both forks or waits without holding any.

Starvation example: Philosophers 1 and 3 repeatedly acquire their forks, eat, and release them. Each time they release their forks, they acquire them again before philosopher 2 can obtain forks 2 and 3. Philosopher 2 could therefore wait forever.

Name and difference: This is called starvation. Deadlock occurs when processes cannot make progress because they are waiting on one another, while starvation occurs when one process waits indefinitely even though other processes continue making progress.

With page size p, the average wasted space per process is approximately p/2 bytes because the last page is usually partially filled. Designers do not simply choose very small pages because smaller pages require more page table entries, increasing memory overhead and address translation management.

B-b Experiment 1, the deadlock. In your own words, say what each thread holds and what each waits for at the moment the detector runs. Then point to the line or lines of naive_transfer where each of the four conditions shows up: mutual exclusion, hold and wait, no preemption and circular wait. Why does the program use the barrier start_line, and what would you expect to see if that line were removed?

In Experiment 1, T1 holds the lock for account 0 and waits for account 1, while T2 holds the lock for account 1 and waits for account 0. This creates a deadlock because neither thread can continue.

All four deadlock conditions appear in `naive_transfer()`. Mutual exclusion occurs when `with LOCKS[src]` allows only one thread to hold each lock. Hold and wait occurs when a thread holds its source lock while attempting to acquire `LOCKS[dst]`. No preemption occurs because another thread cannot forcibly take away a held lock; the owner must release it. Circular wait occurs when T1 waits for T2's lock while T2 waits for T1's lock.

The `start_line.wait()` barrier ensures both threads acquire their first locks before attempting to acquire their second locks, making the deadlock occur consistently. Without the barrier, one thread might complete its transfer before the other acquires its first lock, so deadlock would not be guaranteed.

B-c Experiment 1, recovery and prevention. Which recovery method from Problem 3 does the program use, how does it choose the victim, and what did the recovery cost? Then explain why the three threads of the ring cannot deadlock with ordered_transfer, even though their payments go around a ring. Which condition does the lock order rule out, and what does it cost a programmer? Why is checking that the total is still 1500 a useful test?

The program uses victim selection and rollback to recover from deadlock. It selects T2 because its $50 transfer is smaller than T1's $100 transfer, making it cheaper to redo. T2 releases its lock without transferring any money, allowing T1 to complete its transfer. The recovery cost is the unfinished transfer, which would need to be attempted again.

The three-thread ring avoids deadlock because `ordered_transfer()` always acquires locks in ascending account-number order, regardless of the direction of the payment. This eliminates the circular wait condition, even though the transfers themselves form a ring. The cost to programmers is having to define and consistently follow a global lock ordering rule.

Checking that the total balance remains $1,500 is useful because transfers should only move money between accounts, not create or lose money. It helps verify that the concurrent operations preserve the total amount of money.

B-d Experiment 2. The first time P1 asks for [0, 1, 1] the banker refuses. Show by hand why: give the free vector the tentative grant would leave and every process's remaining need, and show that no process can finish. Why is the same request granted later? Finally, explain the difference between the three outcomes the program prints as error, must wait and refused.

After P3's request was granted, the available resources were [1, 1, 2]. When P1 requested [0, 1, 1], a tentative grant would leave [1, 0, 1] available.

Using Need = Claim − Allocation, the remaining needs after the tentative grant are:

| Process | Remaining Need |
| P1 | [6, 0, 0] |
| P2 | [0, 0, 2] |
| P3 | [0, 2, 3] |
| P4 | [3, 1, 3] |

None of these processes can finish with only [1, 0, 1] available, so no process can release additional resources. The resulting state would be unsafe, which is why the banker refuses the request.

Later, P3 finishes and releases [2, 1, 2], making additional resources available. The same request from P1 can then be granted safely, with the safe sequence P2 → P1 → P3 → P4.

The three outcomes have different meanings. Error means a request exceeds the process's declared maximum claim. Must wait means there are not enough resources currently available. Refused means enough resources are available, but granting the request would put the system into an unsafe state.
